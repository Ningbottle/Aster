# 文献版图：跨平台 Agent Skills 宿主架构

日期：2026-08-15｜主数据库：48 篇｜同行评审：32 篇｜preprint：16 篇

## 研究问题

1. 哪些跨工具差异可以安全地表达为数据？
2. 哪些能力依赖目标工具运行时，必须由专用连接器实现？
3. Skill 的安装、发现、加载、调用和有效性是否可以合并成一个状态？
4. 如何在不过度设计插件系统的前提下，为未来工具保留扩展空间？

## 检索与筛选

检索覆盖 1996-2026，重点集中在 2023-2026。48 篇中，2024 年 15 篇、2025 年 12 篇、2026 年 14 篇；另保留 5 篇软件架构与可变性研究作为基础证据。来源包括 ICLR 9 篇、NeurIPS 7 篇、ACL/Findings 4 篇、EMNLP/Findings 3 篇，以及 ICML、NAACL、LREC-COLING、AIware 和软件工程期刊。

筛选原则：

- Skill 专项研究优先保留，即使 2026 年论文尚为 preprint，但在结论中降低证据权重。
- 工具检索、Agent 安全与真实环境评估优先正式会议论文。
- 软件架构部分只保留直接涉及声明式架构、插件变体或配置/行为分离的论文。
- 不以新闻、论坛或厂商营销材料作为论文数据库证据。

## 主题一：Skill 生命周期与生态（10 篇）

代表文献：[@li2026skillsbench]、[@liu2026wild]、[@han2026swe]、[@xia2026harnessing]、[@liu2026security]。

这一组研究把 Skill 描述为同时包含说明、资源、脚本、触发条件和工具交互的可演化制品，而不是单一 Markdown 文档。最稳定的共同结论是：Skill 的价值取决于质量、相关性、宿主环境和版本。SkillsBench 报告总体平均收益，但存在负向任务；真实 34k Skill 检索环境中的收益明显衰减；SWE-Skills-Bench 则显示软件工程领域的平均收益很小，版本错配会伤害效果。

对 Aster 的含义：

- 必须区分原始制品、解析结果、宿主绑定、部署、会话可见性和调用证据。
- “符合基础格式”只能是结构判断，不能升级为行为兼容结论。
- 兼容记录必须带 Skill 版本和宿主版本。

## 主题二：大规模工具目录、检索与渐进披露（11 篇）

代表文献：[@shi2025toolret]、[@wang2025toolgen]、[@qin2024toolllm]、[@patil2024gorilla]、[@huang2024metatool]。

ToolRet 在 43k 工具语料上显示通用检索器并不天然理解工具选择；ToolGen、ToolLLM 和 Gorilla 分别以生成、专用检索和文档检索处理大规模或变化中的工具集合。MetaTool 进一步显示，同一个工具描述面向不同模型时表现可能不同。

对 Aster 的含义：

- 数据驱动描述适合存储目录位置、语法和基础能力，但不能承担模型选择策略。
- Aster 应保存原始描述与中文说明，不应为了“统一”静默改写原 Skill 描述。
- 目标会话的真实目录只能从宿主确认；Aster 自己扫描到的列表不是运行时真相。
- 大量 Skills 需要分组、过滤与渐进披露，不能一次全部注入。

## 主题三：宿主接口与运行时行为（9 篇）

代表文献：[@yang2024sweagent]、[@liu2024agentbench]、[@trivedi2024appworld]、[@yao2025taubench]。

SWE-agent 的核心结论是 Agent-Computer Interface 本身显著影响模型表现。AgentBench、AppWorld 与 tau-bench 又显示，同一模型在不同环境、工具集合、政策和交互状态下差异很大。ConAgents 把选择、执行和校准拆开，也提供了明确的职责分离证据。

对 Aster 的含义：

- Pi 与 DSH 不能被压成一个假的统一对话/执行接口。
- 进程启动、版本探测、会话目录、调用、取消、权限和错误映射属于宿主连接器。
- 通用工具描述不能包含任意可执行逻辑，否则会变成未经治理的插件系统。

## 主题四：安全、权限与供应链（12 篇）

代表文献：[@debenedetti2024agentdojo]、[@zhan2024injecagent]、[@zhang2025asb]、[@zhu2025melon]、[@liu2026security]。

AgentDojo 与 InjecAgent 证明外部工具内容可通过间接提示注入改变 Agent 行为。ASB 把攻击面扩展到系统提示、用户提示、记忆和工具。MELON、Task Shield、IPIGuard 与 Progent 的共同结构是：关键安全策略必须存在于模型之外的确定性层。2026 Skill 生态研究进一步指出脚本、依赖、来源和升级本身构成供应链风险。

对 Aster 的含义：

- 原始快照、提交固定、文件哈希、差异检查、部署所有权和回滚是第一阶段责任，不是未来增强。
- 工具描述文件不得自行宣称权限、验证结果或信任状态。
- Aster 不执行 Skill 脚本；最终运行权限仍由目标工具决定。
- “仓库已信任”不能掩盖更新中新增的可执行内容。

## 主题五：Coding Agent 配置与上下文文件（4 篇）

代表文献：[@gloaguen2026agents]、[@galster2026configuring]、[@khatri2026context]。

2,853 个仓库的探索研究识别出从静态上下文到可执行集成的多类配置机制，说明不同工具的配置差异不是偶发现象。关于 AGENTS.md 的受控研究结论并不完全一致，但共同表明：配置会改变 Agent 行为和成本，更多上下文不必然更好。

对 Aster 的含义：

- AGENTS.md 应只包含少量非显然、稳定约束。
- 工具差异不应全部塞进项目级上下文，而应由产品数据模型和适配器承担。
- 不应把每个平台的所有字段合并成一个越来越大的“万能 Skill schema”。

## 主题六：声明式配置、插件架构与可变性（5 篇）

代表文献：[@acher2014variability]、[@santos2017variability]、[@habermann1996declarative]。

插件系统研究支持显式建模共同点、变化点、依赖和版本演化；同时也指出，真实插件架构的有效配置不能只靠一张静态清单，需要结合架构、依赖与专家知识。可重配置系统研究反复强调配置与行为分离。

对 Aster 的含义：

- “工具描述”应是一种受限、版本化、可验证的配置，而不是动态代码。
- 对所有目标共同的静态差异可声明化；需要读取运行时状态或改变会话的部分必须编程实现。
- 首发不需要第三方可执行适配器市场；内部稳定接口足以降低未来扩展成本。

## 架构备选比较

| 方案 | 优点 | 主要问题 | 研究判断 |
|---|---|---|---|
| 所有工具硬编码 | 初期直观 | 路径、优先级和字段规则散落，升级容易漂移 | 不推荐 |
| 全部声明化 | 新增工具快 | 无法可靠表达会话、进程、权限与验证；容易制造虚假兼容 | 不推荐 |
| 从第一天开放可执行插件 | 扩展最自由 | 扩大攻击面、版本契约和调试成本 | 第一阶段不推荐 |
| 受限工具描述 + 专用连接器 | 静态差异数据化，运行时差异保留在代码；可测试、可演化 | 需要严格定义边界与证据状态 | 推荐 |

## Phase 2 结论

原结构方向合适，但应正式改名为：

> **受限、版本化的 Host Profile + 具备运行时证据能力的 Host Connector**

其中 Host Profile 只能描述可静态验证的事实；Host Connector 承担版本探测、进程/会话控制、宿主目录观测、重载和实际调用验证。Pi、DSH 首发拥有完整 Connector；其他工具先使用经过官方资料验证的 Profile，必要时增加轻量探测器，而不是一开始建立任意代码插件机制。

Phase 3 将详细阅读 8 篇最相关论文，验证此边界是否经得住方法和实验层面的检查。
